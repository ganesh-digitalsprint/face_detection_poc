# Vault alerts inspection (M0)
- RF-DETR detection, ByteTrack tracking and stable-count sampling run per frame in `VaultRoomManager.process_frame`; tuning is `VaultRoomCountingSettings` in `app/core/ml_config.py` and `config/models.yaml` (`count_stable_seconds`, `stable_min_samples`, `stable_majority_ratio`).
- `DualControlSessionManager.start` creates the credential token; `VaultAuthenticationService.process_frame` verifies custodians and lazily calls `expire_if_needed` (there is no periodic expiry call yet).
- The six-minute vault timer starts in `VaultRoomManager.on_access_granted` through room rules; room `tick` enforces it and calls the door controller on close/expiry.
- The right-panel alerts come from `VaultRoomManager.state()` runtime `open_alerts`, not persisted alert rows.
- The backend has no WebSocket publisher; `/api/v1/vault-room/events` publishes room events and state through Server-Sent Events.
- Route protection uses the optional shared `VAULT_ROOM_API_KEY`; no user/operator model exists.
- Runtime tuning uses YAML validated by Pydantic (`ml_config.py`); schema changes use dated manual SQL files in `migrations/`, not Alembic.
- `VaultRoomAlert`: id, session_id, type, severity, message, opened/closed timestamps, counts, duration, title/source, camera, first/last seen, occurrence count, created/updated, status and actor timestamps, incident_id, metadata_json.
- `VaultIncident`: id, incident_number, title/description, status/severity, session_id/camera_id, opened/updated/resolved times, created_by, retention_hold, metadata_json.
- `VaultEvidence`: id, incident_id/alert_id, evidence type, Cloudinary identifiers/delivery data, dimensions/size/MIME, capture/upload times, uploader, session/camera, comment/checksum/available, metadata_json.
- `VaultAuditEvent`: id, actor_id, action, entity_type/id, created_at, details.
- `VaultMonitoringRepository` provides alert create/list/get/transition; incident create/get; evidence add/get/list; comment add; and retention candidate lookup. `get_evidence` and `list_incident_evidence` are duplicated definitions.
